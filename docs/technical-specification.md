# Техническое задание SavranPay

## 1. Общие сведения

**Наименование системы:** SavranPay.

**Тип продукта:** банковский сервис перевода денежных средств.

**Технологическая платформа:** C#/.NET, Vue 3, TypeScript.

**Правовая модель:** сервис разрабатывается для банка, небанковской кредитной организации либо финтех-компании, работающей по договору с лицензированной кредитной организацией.

## 2. Назначение

SavranPay предназначен для безопасного создания, проверки, подтверждения, исполнения и учета переводов денежных средств между клиентами банка, между собственными счетами клиента и во внешние платежные контуры.

Система должна обеспечивать:

1. Создание распоряжения клиента на перевод.
2. Проверку клиента, счета, реквизитов и лимитов.
3. AML/KYC-контроль.
4. Антифрод-проверку.
5. Криптографическое подтверждение операции.
6. Идемпотентную обработку переводов.
7. Ledger-учет денежных операций.
8. Аудит всех действий.
9. Уведомление клиента.
10. Подготовку продукта к промышленной эксплуатации.

## 3. Границы MVP

В MVP входят:

1. Backend API для переводов.
2. Личный кабинет клиента.
3. Модуль счетов.
4. Модуль переводов.
5. Модуль подтверждения операций.
6. Модуль лимитов.
7. Mock AML/KYC.
8. Mock антифрод.
9. Ledger-модуль.
10. Mock уведомления.
11. Модуль аудита.
12. Модуль спорных операций.
13. Тестовый стенд.
14. Документация API.
15. Модель угроз.

## 5. Безопасность MVP

В текущей версии реализованы:

1. HTTPS redirect на локальный порт `5001`.
2. HSTS для production-среды.
3. Content-Security-Policy.
4. `X-Content-Type-Options: nosniff`.
5. `X-Frame-Options: DENY`.
6. `Referrer-Policy: no-referrer`.
7. `Permissions-Policy`.
8. `Cache-Control: no-store`.
9. `Idempotency-Key` для создания перевода.
10. Nonce и timestamp для подтверждения операции.
11. Защита от повторного использования nonce.
12. Constant-time comparison подписи.

## 6. Криптографическая модель MVP

В демонстрационной версии используется HMAC-SHA-256 для показа принципа криптографической привязки подтверждения к параметрам операции.

Подписываются:

1. ID операции.
2. Счет списания.
3. Счет получателя.
4. БИК банка получателя.
5. Имя получателя.
6. Сумма.
7. Валюта.
8. Назначение платежа.
9. Время создания.
10. Nonce.
11. Timestamp.

Для production данная модель должна быть заменена на WebAuthn/Passkeys, мобильную подпись, СКЗИ, HSM/KMS или иной механизм, утвержденный банком и регулятором.

## 7. Ограничения текущей реализации

1. Данные хранятся в памяти процесса.
2. Нет постоянной БД и миграций.
3. Нет настоящего OAuth/OIDC.
4. Нет production-grade RBAC/ABAC.
5. Нет реального HSM/KMS.
6. Нет реальных внешних интеграций.
7. Vue-кабинет пока встроен в `wwwroot`.
